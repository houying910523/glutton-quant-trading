# 数据接入与标准化存储方案

## 1. 目标

这份文档只覆盖首版必须项中的两件事：

1. 数据接入
2. 数据标准化与存储

目标不是做一个“什么都能接”的数据平台，而是做出足够支撑研究、信号生成和回测的稳定底座。

## 2. 方案范围

首版只接以下数据：

- 标的基础信息
- 交易日历
- 日线行情

首版不接：

- Tick
- L2 盘口
- 实时推送流
- 新闻与公告正文
- 券商账户数据

## 3. 总体方案

```text
外部数据源
-> 接入适配器
-> 原始层落盘
-> 标准化清洗
-> 标准层入库
-> 生成研究数据集
-> 提供给策略与回测
```

这个流程必须满足 4 个要求：

- 可重跑：同一批数据可以重复导入，不写坏数据
- 可追溯：知道一条标准数据来自哪个源、哪次抓取
- 可校验：能发现缺失、重复、异常价格和时间错位
- 可演进：后续扩展新数据源时，不改内部统一模型

## 4. 数据源策略

## 4.1 首版接入策略

首版不追求同时对接多个源。每类数据先指定一个主数据源，必要时才引入备用源。

建议策略：

- 标的基础信息：单一主源
- 交易日历：单一主源
- 日线行情：单一主源

原因很简单：

- 多源对齐本身就是一个复杂系统
- 首版更重要的是把内部数据模型和入库流程做稳定

## 4.2 接入适配器职责

每类外部源都通过 adapter 接入，但 adapter 只做三件事：

- 拉取数据
- 把外部字段映射为原始记录
- 记录抓取批次元信息

adapter 不负责：

- 直接拼成策略可用宽表
- 直接覆盖已有标准层数据

这些工作统一由标准化层处理。

## 5. 数据接入设计

## 5.1 接入批次 Batch

所有抓取都按批次管理，最少记录以下信息：

| 字段 | 说明 |
| --- | --- |
| `batch_id` | 抓取批次 ID |
| `source_name` | 数据源名称 |
| `resource_type` | 数据类型，例如 `daily_quote` |
| `request_params` | 请求参数 |
| `started_at` | 开始时间 |
| `finished_at` | 结束时间 |
| `status` | `pending` / `running` / `success` / `failed` |
| `row_count_raw` | 原始记录数 |
| `error_message` | 失败信息 |

## 5.2 接入任务拆分

首版建议拆成 3 类任务：

1. `sync_stocks`
2. `sync_trading_calendar`
3. `sync_daily_quotes`

每个任务都应该支持：

- 全量初始化
- 按日期增量同步
- 指定标的重刷

## 5.3 幂等要求

接入流程必须幂等。重复跑同一批次，不得造成重复数据。

实现上直接要求：

- 原始层按 `batch_id + source_primary_key` 去重
- 标准层按业务唯一键 upsert
- 批次失败时不把半成品标记为标准数据成功

## 6. 标准化设计

## 6.1 标准化输入

标准化层只吃原始层数据，不直接拉外部接口。

输入包括：

- 原始记录
- 数据源元信息
- 业务规则配置

## 6.2 标准化输出

标准化层输出以下标准对象：

- `Stock`
- `TradingCalendar`
- `DailyQuote`

这些对象的字段定义以 [05-数据模型设计](./05-数据模型设计.md) 为准。

## 6.3 标准化规则

### 标的基础信息

- 统一生成 `stock_id`
- 统一交易所代码和市场代码
- 统一名称和状态字段
- 映射最小交易单位

### 交易日历

- 每个自然日都允许产生日历记录
- 非交易日标记 `is_open = false`
- 只保留 `trade_date` 和 `is_open`

### 日线行情

- 统一交易日字段为 `trade_date`
- 统一价格字段命名为 `open/high/low/close`
- 成交量、成交额统一单位
- 保持一条日线记录只表达一个交易日的原始行情事实
- 标准记录保留 `ingestion_batch_id` 作为追溯依据

## 7. 质量校验

首版必须有最小数据质量门槛，否则回测不可信。

## 7.1 通用校验

- 主键不得重复
- 必填字段不得为空
- 时间字段格式必须合法
- 数值字段类型必须正确

## 7.2 日线行情校验

- `high >= open`
- `high >= close`
- `low <= open`
- `low <= close`
- `high >= low`
- 成交量不能为负
- 同一标的交易日不能重复
- `trade_date` 必须对应开市日历中的开市日

## 7.3 日历校验

- 同一市场同一日只有一条记录
- `trade_date` 必须合法

## 7.4 校验失败处理

- 原始层数据保留
- 标准层不写入失败记录
- 失败批次必须记录错误摘要
- 允许按批次重试

## 8. 存储方案

## 8.1 三层存储

### Raw Layer

用途：

- 保留原始响应
- 便于排查源数据问题
- 支持标准化逻辑重跑

建议存储形式：

- 本地文件
- 原始 JSONL

### Standard Layer

用途：

- 作为系统内部唯一可信数据源
- 提供稳定的表结构给研究和回测

建议存储形式：

- 关系型数据库或列式表存储
- 表结构按核心实体拆分

### Serving Layer

用途：

- 面向策略研究和回测的高频读取
- 生成固定口径数据集

说明：

- 这一层不属于首版最小交付
- 首版先以标准层作为研究和回测直接读取来源

建议存储形式：

- 预处理后的宽表
- Parquet 数据切片
- 数据集视图

## 8.2 首版表清单

标准层必须有：

- `trading_calendar`
- `stock`
- `daily_quote`

服务层建议有：

- `research_dataset_spec`
- `backtest_result`

## 8.3 索引与本地存储建议

首版直接锁定以下策略：

- `daily_quote` 不强依赖数据库分区，本地单机实现优先保证唯一索引和按日期查询索引
- `daily_quote` 建 `(stock_id, trade_date)` 唯一索引
- `daily_quote` 建 `(trade_date, stock_id)` 查询索引
- `trading_calendar` 建 `(market, trade_date)` 唯一索引

## 9. 更新节奏

首版按离线批处理设计，不做实时流。

推荐节奏：

- 标的基础信息：每日一次或有变更时重刷
- 交易日历：初始化一次，定期校验补全
- 日线行情：每个交易日收盘后更新

## 10. 研究与回测读取约定

首版策略与回测直接读取标准层，不允许直接读原始层。

读取默认约定：

- 默认频率：`1d`
- 默认价格口径：前复权日线价格
- 默认过滤：剔除无效标的
- 默认时间轴：以交易日历为准，而不是自然日

## 11. 首版完整交付物

如果要说“1 和 2 做完了”，至少应交付以下内容：

### 数据接入

- 3 个同步任务定义
- adapter 接口约定
- 批次元信息模型
- 原始层落盘规则

### 数据标准化与存储

- 标准化规则清单
- 标准层表结构
- 数据质量校验规则
- 索引和 upsert 规则

## 12. 实现顺序

推荐按这个顺序实现：

1. `stock` / `trading_calendar`
2. `daily_quote`
3. 原始层批次管理
4. 标准化流水线
5. `backtest_result`

原因：

- 没有标的和日历，行情无法正确落库
- 没有行情，回测输入不完整
- 没有批次和校验，后续排查成本会迅速失控

## 13. 明确不做的事情

- 不为未来实盘先设计订单与账户表
- 不为未来高频先设计 tick 和 L2
- 不在 adapter 内直接做策略级特征工程
- 不在首版引入多源仲裁和主备切换
- 不在首版引入复权计算和交易状态模型
