# 数据接入与标准化存储方案

## 1. 文档目的

这份文档只描述**当前代码已经落地**的数据接入、标准化存储和对外入口。

基准文件包括：

- `modules/datasource/`
- `modules/repositories/`
- `modules/controller/`
- `modules/app.py`
- `sql/*.sql`

它主要回答 4 个问题：

1. 当前接了哪些数据
2. 这些数据如何进入 SQLite 标准层
3. 标准层之上，指标如何被物化和查询
4. 当前项目已经有哪些 CLI / HTTP 入口

## 2. 当前实现范围

当前正式实现已经覆盖 3 条主线：

### 2.1 标准层数据接入

已落地资源：

- `stock_info`
- `trading_calendar`
- `stock_daily`
- `ingestion_batch`

### 2.2 研究侧指标物化与查询

已落地能力：

- `indicators` 表管理指标定义
- 指标按年写入 Parquet 分区
- `refresh_indicators.py` 增量续算
- `IndicatorService` 基于 DuckDB 读取并拼接指标数据集

### 2.3 API 与研究原型入口

已落地入口：

- FastAPI 运行时：`modules/app.py`
- 股票查询接口：`/api/stock/*`
- 选股接口：`/api/selection/*`
- 指标查询接口：`/api/indicator/*`
- Typer CLI：`sync_stock_info.py`、`sync_trading_calendar.py`、`sync_stock_daily.py`、`refresh_indicators.py`

当前明确不覆盖：

- Tick / L2 / 实时推送
- 多数据源仲裁与自动 fallback
- 订单、账户、成交、持仓
- 真正可运行的回测引擎
- Raw Layer 的正式落盘流程

## 3. 当前主链路

### 3.1 股票基础信息同步链路

```text
sync_stock_info.py
-> StockInfoPipeline
-> create_running_batch()
-> AkshareStockAdapter.fetch()
-> StockInfoRepository.upsert_many()
-> BatchRepository.complete_batch()
```

### 3.2 交易日历同步链路

```text
sync_trading_calendar.py
-> TradingCalendarPipeline
-> AkshareTradingCalendarAdapter.fetch(start_date, end_date)
-> 对自然日区间逐天展开
-> TradingCalendarRepository.upsert_many()
-> BatchRepository.complete_batch()
```

### 3.3 日线行情同步链路

```text
sync_stock_daily.py
-> StockDailyPipeline
-> 读取 active stock_info
-> 根据 stock_daily 最新落库日期推导增量起点
-> 读取 trading_calendar 中未来应补的开市日
-> AkshareDailyQuoteAdapter.fetch(..., adjust="qfq")
-> StockDailyRepository.upsert_many()
-> BatchRepository.complete_batch()
```

### 3.4 指标刷新链路

```text
refresh_indicators.py
-> 读取 indicators 中 active 定义
-> StockDailyService.load_stock_daily()
-> load_indicator(definition)
-> Indicator.compute()
-> IndicatorStore.write_year_partition()
-> IndicatorRepository.set_last_materialized_date()
```

### 3.5 指标查询链路

```text
IndicatorController.get_indicator_detail()
-> IndicatorService.get_indicator_dataset()
-> DuckDB read_parquet(...)
-> 按 trade_date + instrument_id 拼接多个指标分区
-> controller 最终输出 JSON 列表
```

## 5. 当前数据源与抓取接口

当前程序化主数据源只有一个：

- `AkShare`

当前没有实现：

- `Tushare`
- 主备切换
- 多源对账
- 自动 fallback

当前抓取接口按资源拆分：

- `StockFetcher.fetch()`
- `TradingCalendarFetcher.fetch(start_date, end_date)`
- `StockDailyQuoteFetcher.fetch(symbol, start_date, end_date, stock_id, batch_id)`

这与当前 pipeline 的粒度一一对应。

## 6. 当前数据库与存储布局

### 6.1 SQLite 标准层

当前 schema 由 `SQLiteSchemaManager` 顺序执行 `sql/*.sql` 初始化。

当前已建表：

- `ingestion_batch`
- `stock_info`
- `trading_calendar`
- `stock_daily`
- `indicators`
- `factors`（预留）
- `strategies`（预留）

默认路径：

- 数据库：`data/system/glutton.db`

### 6.2 Parquet 指标层

当前指标根目录：

- `data/indicators`

目录规则：

```text
data/indicators/{storage_key}/
  year=2024/
    data.parquet
  year=2025/
    data.parquet
```

其中：

- 一个 `storage_key` 对应一个指标数据集
- 一个数据集按年分区
- 分区文件固定名为 `data.parquet`

### 6.3 Raw Layer 当前状态

配置里预留了：

- `data/raw`
- `DEFAULT_RAW_ROOT`

但要注意：

- 当前 pipeline **没有**把原始抓取结果正式写入 `data/raw`
- 也没有 `manifest.json` / `records.jsonl` 的主流程落盘

因此当前项目的真实主链路是：

> 直接从 adapter 规范化成 record，再写 SQLite / Parquet

## 7. 当前标准化约定

### 7.1 `stock_info`

- `market = CN`
- `exchange in {SSE, SZSE}`
- `currency = CNY`
- `lot_size = 100`
- `instrument_id` 由 `exchange + symbol` 派生，不单独存表

### 7.2 `trading_calendar`

- adapter 返回开市日集合
- pipeline 按自然日区间逐天展开
- 在开市日集合中的日期写为 `is_open = 1`
- 其余自然日写为 `is_open = 0`

### 7.3 `stock_daily`

- `open/high/low/close` 存整数分
- `volume` 存整数股
- `amount` 当前按整数金额存储
- `turnover` 按原始换手率乘 `10000` 存储
- `stock_id` 和 `ingestion_batch_id` 在 pipeline 阶段注入
- 当前抓取固定使用 `adjust="qfq"`，因此标准层日线是前复权口径

### 7.4 `indicators`

当前定义记录包含：

- `indicator_id`
- `version`
- `indicator_name`
- `category`
- `compute_ref`
- `params`
- `output_columns`
- `storage_key`
- `status`
- `last_materialized_date`

其中：

- `(indicator_id, version)` 唯一
- `storage_key` 唯一
- `compute_ref` 使用 `module.path:ClassName`

## 8. 当前同步行为

### 8.1 股票基础信息

- 以全量快照方式同步
- 当前会抓取沪深在市与已退市基础信息
- 通过自然键 `(market, exchange, symbol)` upsert

### 8.2 交易日历

- 必须显式提供 `start_date` 和 `end_date`
- pipeline 负责把“只有开市日”的外部结果扩成完整自然日区间

### 8.3 日线行情

- 按股票增量续跑
- 若本地已有历史，则从最新落库日期的下一天开始
- 若本地没有历史，则从 `listed_at` 或默认起点 `1991-01-01` 开始
- 同步终点取本地交易日历中不晚于今天的最后一个开市日
- 并发抓取由 `ThreadPoolExecutor` 完成

### 8.4 指标刷新

- 通过 `modules/indicators/scripts/refresh_indicators.py` 执行
- 默认读取 `indicators` 表里全部 active 指标
- 根据 `last_materialized_date` 自动推进起始日期
- 以“年”为写盘粒度
- 年内部分重算时会先读旧分区再合并覆盖

## 10. 当前质量与边界

当前已落地的最小校验包括：

- Pydantic 模型校验
- SQLite 唯一键、外键与检查约束
- `stock_daily` 的 OHLC 合法性校验
- 指标 `compute_ref`、`output_columns`、`storage_key` 基本校验
- pipeline 批次状态跟踪

当前还没有正式落地：

- Raw Layer 正式写盘
- 数据质量 issue 表
- 缺口检测与自动修复
- 多数据源一致性校验
- 真正可运行的回测执行链路

## 11. 当前结论

当前数据底座已经明确形成两层：

1. `AkShare + pipeline + SQLite`：负责股票、交易日历、前复权日线与批次追踪
2. `indicators + Parquet + DuckDB`：负责研究侧指标物化与查询

在这个基础上，仓库又向上长出了：

- FastAPI 查询接口
- 过滤器与选股原型
- 多因子策略原型

但回测、订单、账户、实盘仍未进入主流程。
