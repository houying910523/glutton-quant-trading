# 数据接入与标准化存储方案

## 1. 文档目的

这份文档合并了原来的“方案说明”和“详细设计”两份文档，只保留当前代码已经落地或直接对应的内容。

它只回答 3 个问题：

1. 当前接了哪些数据
2. 这些数据如何进入标准层
3. 标准层之上，指标数据如何物化存储

它不讨论实盘、订单、账户，也不展开未来的 Serving Layer。

## 2. 当前实现范围

当前正式实现覆盖两条链路：

### 2.1 标准层数据接入

- `stock`
- `trading_calendar`
- `daily_quote`
- `ingestion_batch`

### 2.2 研究侧指标物化

- `indicator_definition`
- 指标按月写入 Parquet 分区
- 指标刷新脚本与增量续算

当前明确不覆盖：

- Tick / L2 / 实时推送
- 多数据源仲裁
- Serving Layer
- `data_quality_issue` 正式表
- DuckDB 查询层

## 3. 当前主链路

### 3.1 标准层接入链路

```text
AkShare
-> 资源级 fetcher
-> pipeline 创建 ingestion_batch
-> Raw manifest 落盘
-> 标准化为记录对象
-> SQLite upsert
-> 更新批次统计
```

### 3.2 指标刷新链路

```text
indicator_definition
-> refresh_indicators.py
-> StockDailyService 读取标准层日线
-> Indicator.compute()
-> data/indicators/{storage_key}/year=YYYY/month=MM/data.parquet
-> 回写 last_materialized_date
```

## 4. 当前目录与模块

当前实现主要集中在这些位置：

```text
modules/
  config.py
  datasource/
    adaptors/
    pipeline/
    scripts/
    service/
  indicators/
    builtin/
    scripts/
    storage/
  repositories/
sql/
  001_initial_schema.sql
  002_indicator_definition.sql
  003_seed_indicator_definitions.sql
```

职责如下：

- `modules/datasource/adaptors/`：封装 AkShare 调用和资源级抓取协议
- `modules/datasource/pipeline/`：批次管理、Raw manifest、标准表写入
- `modules/datasource/scripts/`：数据同步 CLI 入口
- `modules/datasource/service/stock_daily_service.py`：面向研究侧读取标准层日线
- `modules/indicators/`：指标定义、内置指标、Parquet 存储与刷新逻辑
- `modules/repositories/`：SQLite 连接、schema 初始化、repository 封装

## 5. 当前数据源与抓取接口

当前程序化主数据源只有一个：

- `AkShare`

当前没有实现：

- `Tushare Pro`
- 主备切换
- 自动 fallback

当前抓取接口按资源拆分，而不是强行抽成一个统一 `fetch(request)`：

- `StockFetcher.fetch()`
- `TradingCalendarFetcher.fetch(start_date, end_date)`
- `StockDailyQuoteFetcher.fetch(symbol, start_date, end_date, stock_id, batch_id)`

这样做是因为 3 类资源的抓取参数和同步粒度本来就不同。

## 6. 当前数据库与存储布局

### 6.1 SQLite 标准层

当前 schema 由 `sql/*.sql` 顺序初始化，正式表包括：

- `ingestion_batch`
- `stock`
- `trading_calendar`
- `daily_quote`
- `indicator_definition`

默认路径：

- 数据库：`data/system/glutton.db`

### 6.2 Raw Layer

当前 Raw Layer 目录在：

- `data/raw`

当前主流程默认只写：

- `manifest.json`

`records.jsonl` 仍只是 helper，尚未接入默认流程。

### 6.3 指标 Parquet 层

当前指标根目录在：

- `data/indicators`

一个 `indicator_definition` 对应一个数据集目录，按月分区：

```text
data/indicators/{storage_key}/
  year=2025/
    month=01/
      data.parquet
```

## 7. 当前标准化约定

### 7.1 `Stock`

- `market = CN`
- `exchange in {SSE, SZSE}`
- `asset_type = stock`
- `currency = CNY`
- `lot_size = 100`

### 7.2 `TradingCalendar`

- pipeline 对自然日区间逐天展开
- adapter 返回的开市日集合记为 `is_open = true`
- 其余日期记为 `is_open = false`

### 7.3 `DailyQuote`

- `open/high/low/close` 存整数分
- `volume` 存整数股
- `turnover` 存整数分
- `stock_id` 和 `ingestion_batch_id` 在 pipeline 阶段注入

### 7.4 `IndicatorDefinition`

当前定义记录包括：

- `indicator_id`
- `version`
- `compute_ref`
- `params`
- `output_columns`
- `storage_key`
- `status`
- `last_materialized_date`

其中：

- `(indicator_id, version)` 唯一
- `storage_key` 唯一
- `compute_ref` 采用 `module.path:ClassName` 格式

## 8. 当前同步行为

### 8.1 股票基础信息

- 全量快照同步

### 8.2 交易日历

- 必须显式提供 `start_date` 和 `end_date`
- 在 pipeline 中展开自然日区间

### 8.3 日线行情

- 按股票增量续跑
- 如果本地已有历史，则从最新落库日期的下一天开始
- 如果本地没有历史，则从 `listed_at` 或默认起点 `1991-01-01` 开始
- 同步终点取本地交易日历中不晚于今天的最后一个开市日

### 8.4 指标刷新

- 通过 `modules/indicators/scripts/refresh_indicators.py` 执行
- 按 `indicator_definition` 读取 active 指标
- 根据 `last_materialized_date` 自动推进起始日期
- 以“月”为重算与写盘粒度
- 当月部分重算时会先读旧分区再合并覆盖

## 9. 当前质量与边界

当前已落地的最小校验包括：

- `Pydantic` / `pydantic` 模型校验
- SQLite 唯一键与外键约束
- `daily_quote` 的 OHLC 合法性约束
- 指标 `storage_key`、`output_columns`、`compute_ref` 基本校验

当前还没有正式落地：

- `data_quality_issue` 表
- 覆盖率告警
- 自动缺口修复
- 指标统一查询层

## 10. 当前结论

当前数据底座已经不是“只有接入没有研究”的状态，而是两层结构：

1. 用 AkShare + pipeline 把股票、交易日历和日线行情收口到 SQLite 标准层
2. 用 `indicator_definition + refresh_indicators` 把研究侧指标物化到 `data/indicators` 下的 Parquet 分区

这就是当前代码真正稳定的边界；更上层的研究查询、策略运行和回测，再在这个基础上继续补。
