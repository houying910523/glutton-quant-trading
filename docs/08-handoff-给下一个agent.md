# Handoff：给下一个 Agent 的交接说明

## 1. 当前阶段

`饕餮` 当前还处于文档驱动阶段，目标不是直接进入完整实现，而是把首版 MVP 的详细设计补齐。

到目前为止，已经完成的是：

- 系统总览和首版范围收敛
- 通用架构与 A 股示例边界梳理
- 首版数据模型设计
- 首版数据接入与标准化存储方案
- 首版策略接口与回测接口设计

当前还没有开始代码实现，也没有数据库 schema、API、目录结构和测试计划的详细设计稿。

## 2. 已锁定决策

这些决策已经明确，不要在没有新指令的情况下重新讨论：

### 2.1 首版 MVP 只做 4 个模块

- 数据接入
- 数据标准化与存储
- 策略信号
- 回测引擎

### 2.2 首版明确延后

- 组合构建
- 风险控制
- 订单管理
- 账户与持仓状态
- 调度、日志、监控、告警
- 模拟盘与实盘

### 2.3 数据边界已经收窄

首版数据侧只保留：

- `Stock`
- `TradingCalendar`
- `DailyQuote`
- `ResearchDatasetSpec`
- `BacktestResult`

已经明确不做：

- 复权计算
- 交易状态模型
- Tick / L2
- 订单、成交、账户、持仓数据模型

### 2.4 回测结果表已合并

`BacktestRun` 和 `BacktestMetric` 已合并为 `BacktestResult`。

除非后续明确引入异步任务中心、分步计算或多版本指标快照，否则不要再拆回两张表。

### 2.5 策略接口已经锁定基本方向

- 策略按“交易日切片”输入
- 策略只生成信号，不负责仓位与下单
- 首版信号形态是 `long/flat + score`
- 回测引擎内部使用固定规则解释信号：`top_n + 等权 + 固定再平衡 + next_open`

## 4. 下一个 Agent 应该做什么

建议按下面顺序继续详细设计。

### 第一优先级

补 `首版数据源选型与 adapter 接口设计`，至少写清：

- 首版准备选哪个主数据源
- 每类数据的 adapter 输入输出
- 原始层抓取格式
- 批次管理字段与失败重试约束
- 增量同步与重刷策略

### 第二优先级

补 `回测明细产物与报告结构设计`，至少写清：

- 回测除了 `backtest_result` 之外，还需要哪些非正式明细产物
- 权益曲线、每日收益、信号明细是否落文件还是落表
- 报告结构包含哪些固定章节和图表
- 哪些产物是调试用，哪些是正式结果

### 第三优先级

如果前两者已经完成，再进入更接近实现的设计：

- 项目目录结构设计
- 首版数据库 schema 设计
- 首版 TypeScript 类型定义稿
- 首版测试方案

## 5. 不要做的事情

下一个 agent 不应在这个阶段做以下事情，除非用户明确要求：

- 不要直接开始写大量业务代码
- 不要把组合构建或风险控制偷偷加回首版
- 不要重新引入复权计算和交易状态模型
- 不要先设计实盘接口再反推研究/回测接口
- 不要把当前简单接口抽象成插件系统或工厂体系
- 不要因为“未来可能要用”就补大量可配置项

## 6. 详细设计的验收标准

下一阶段产出的详细设计，至少要满足以下要求：

- 实现者读完后可以直接开始编码，不需要再决定接口长什么样
- 每份设计都要明确输入、输出、字段、约束、错误处理
- 所有新增设计必须和 `05`、`06`、`07` 保持一致
- 如果必须修改既有决策，要在文档中显式写出“为什么改”

## 7. 当前仓库状态

- `src/` 还没有正式实现
- `../modules/test/` 还没有正式测试
- `docs/` 已经是当前项目最完整、最可信的设计入口

因此下一个 agent 的第一职责不是“猜测怎么实现”，而是沿着现有文档把详细设计补齐。

## 8. 建议的起手式

下一个 agent 最稳妥的开工方式：

1. 先读 `05`、`06`、`07`
2. 写 `首版数据源选型与 adapter 接口设计`
3. 再写 `回测明细产物与报告结构设计`
4. 最后再进入 schema / 类型 / 测试设计

如果要挑战现有边界，先说明理由，再改文档，不要直接跳到实现。
