# 策略单时点决策与运行控制

## 当前代码结论

当前仓库的策略接口与回测执行流已经围绕显式决策模型展开。

以当前代码为准，可以把现状总结为：

- `BaseStrategy` 采用 `decide(context, portfolio_state) -> StrategyDecision`
- `FactorScoreStrategy` 使用 `decide()` 输出目标仓位建议
- `modules/backtest/` 已提供输入输出模型、调仓日调度器、分析器和 runner
- `BacktestEngine.run()` 已能驱动 `strategy.decide()`、按 `next_open` 成交、推进组合状态并生成净值曲线
- 当前已加入 A 股 `T+1`、整手买入和一字涨跌停的保守约束
- 停牌处理细化、闭合交易和更完整的市场规则仍待补齐

## 当前接口现实

### `BaseStrategy`

位置：`modules/strategies/base.py`

```python
class BaseStrategy(Protocol):
    meta: StrategyMeta

    def decide(
        self,
        context: Context,
        portfolio_state: PortfolioState,
    ) -> StrategyDecision: ...
```

当前策略层接口就是：

```text
(context, portfolio_state) -> StrategyDecision
```

也就是：

- 策略负责决策
- runner / engine 负责状态推进与执行

### `FactorScoreStrategy`

位置：`modules/strategies/factor_score_strategy.py`

当前实现特点：

- `decide()` 接受 `Context` 和 `PortfolioState`
- 在 `decide()` 中计算因子分数和目标持仓
- 返回 `StrategyDecision`
- 输出 `targets`，并设置 `close_missing_positions=True`

当前策略执行形态为：

```text
Context + PortfolioState -> decide() -> StrategyDecision
```

## 当前边界

### 策略层当前已经负责

- 因子计算结果汇总
- 排序与打分
- 目标持仓解释
- 产出 `StrategyDecision`

### 上层系统当前已经具备最小闭环

- 调仓日调度器：`RebalanceScheduler`
- 回测输入输出模型：`BacktestConfig`、`PortfolioState`、`BacktestResult`
- 结果分析器：`BacktestAnalyzer`
- runner 入口：`BacktestRunner`
- 回测执行流：`BaseStrategy.decide()` → `next_open` 成交 → 收盘估值 → 净值曲线 / 持仓快照 / 订单成交记录
- 已实现的 A 股保守约束：`T+1`、整手买入、一字涨跌停拦截

### 上层系统当前还没有完成

- 更完整的停牌与涨跌停细化规则
- 闭合交易生成
- 在实盘中做委托执行
- 持久化策略状态

## 当前最合适的表述

如果只按照当前实现来描述，应当写成：

- **策略采用显式状态输入接口**；
- **真实组合状态由引擎 / runner 维护，并作为 `portfolio_state` 传入策略**；
- **回测层已经具备最小运行控制闭环**，并且已经开始承接 A 股基础执行约束；
- **as-of 语义已经在回测主流程里落实**，后续主要补市场规则细节与交易闭合能力。

## 后续收口建议

结合当前代码，下一步更现实的收口方式是：

1. 继续增强 `BacktestEngine.run()` 的停牌、涨跌停细化和更多市场规则；

3. 用 `PortfolioState` 承接成交后的真实状态推进；
