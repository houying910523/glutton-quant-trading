# 策略单时点决策与运行控制

## 核心结论

- **策略只负责单时点决策**：给定某个 `as_of_date` 以及该日可见的数据，输出该日信号。
- **回测和实盘的区别不在策略层，而在上层运行器**：
  - 实盘：只对最新交易日调用一次策略。
  - 回测：对历史调仓日逐次调用同一个策略。
- **不要让策略直接生成整个时间区间的信号**，否则容易引入未来数据泄漏，也会把策略逻辑和运行调度耦合。
- **统一原则是 as-of 语义**：策略输入的数据必须严格限定为“截至当前决策日可见的数据”。
- **如果策略需要状态**（如持仓天数、冷却期、分批加仓），也应由上层系统负责保存和推进状态，而不是在策略里区分“回测模式 / 实盘模式”。

## 推荐边界

### 策略层
只做：

- 截至当前日期的数据计算
- 过滤、排序、打分
- 输出该日信号

### 上层系统
负责：

- 生成调仓日
- 准备每个日期的可见数据切片
- 循环调用策略
- 在回测中解释成持仓、成交和收益
- 在实盘中把信号交给执行模块

## 推荐统一范式

```text
(as_of_date, visible_data, optional_state) -> decision
```

其中：

- `decision` 是策略输出
- `visible_data` 必须满足 as-of 语义
- `optional_state` 仅在策略确实有路径依赖时才需要

## 不推荐的做法

不要在策略内部写：

```python
if mode == "backtest":
    ...
elif mode == "live":
    ...
```

这样会让同一策略出现两套决策路径，增加回测和实盘不一致的风险。
