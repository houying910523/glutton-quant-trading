# 数据模型设计

## 1. 目标

这份文档只描述**当前代码里真实存在**的数据模型边界，基准来自：

- `sql/*.sql`
- `modules/repositories/models.py`
- `modules/indicators/models.py`
- `modules/core/context.py`
- `modules/strategies/models.py`

它不再描述尚未落地的通用 `ResearchDatasetSpec`、正式 `BacktestResult` 明细表等未来对象。

## 2. 当前模型分层

当前仓库里的模型大致分成 4 层：

1. **SQLite 持久化模型**：真正建表并落库
2. **指标运行时模型**：用于刷新和查询指标
3. **研究/筛选运行时模型**：用于 `Selection`、`Filter`、`Factor`
4. **策略/回测运行时模型**：用于策略原型；回测仍大多占位

## 3. SQLite 持久化模型

当前 schema 由 `SQLiteSchemaManager` 按 `sql/*.sql` 顺序执行初始化。

### 3.1 `ingestion_batch`

用途：记录一次数据同步批次的元信息和统计结果。

对应代码：

- SQL：`sql/001_initial_schema.sql`
- 模型：`IngestionBatchRecord`
- Repository：`BatchRepository`

核心字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer | 主键 |
| `batch_key` | text | 批次唯一键，形如 `stock_daily_2025-10-08_001` |
| `source_name` | text | 当前主要为 `akshare` |
| `resource_type` | text | `stock_info` / `trading_calendar` / `stock_daily` |
| `sync_mode` | text | `full` / `incremental` / `refresh` |
| `start_date` / `end_date` | text | 本次同步区间 |
| `request_params` | text | JSON 字符串 |
| `status` | text | `pending` / `running` / `success` / `failed` |
| `raw_count` | integer | 抓取原始记录数 |
| `valid_count` | integer | 通过校验的记录数 |
| `loaded_count` | integer | 成功落库数 |
| `rejected_count` | integer | 拒绝数 |
| `retry_count` | integer | 历史失败重试次数 |
| `error_summary` | text | 错误摘要 |
| `started_at` / `finished_at` | text | 批次执行时间 |
| `created_at` / `updated_at` | text | 记录创建/更新时间 |

说明：

- 这是当前所有 pipeline 的公共元数据表。
- `stock_daily.ingestion_batch_id` 会回指这里，形成最基本的数据追溯链路。

### 3.2 `stock_info`

用途：保存股票基础信息。

对应代码：

- SQL：`sql/001_initial_schema.sql`
- 模型：`StockInfoRecord`
- Repository：`StockInfoRepository`

核心字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer | 主键 |
| `market` | text | 当前固定为 `CN` |
| `exchange` | text | `SSE` / `SZSE` |
| `symbol` | text | 六位证券代码 |
| `ticker` | text | 当前通常与 `symbol` 相同 |
| `name` | text | 股票名称 |
| `currency` | text | 当前固定为 `CNY` |
| `lot_size` | integer | 当前固定为 `100` |
| `listed_at` / `delisted_at` | text | 上市/退市日期 |
| `status` | text | `active` / `delisted` |
| `optional` | integer | 自选标记，`0/1` |
| `created_at` / `updated_at` | text | 创建/更新时间 |

约束：

- `(market, exchange, symbol)` 唯一
- `exchange` 只允许 `SSE`、`SZSE`
- `currency` 当前只允许 `CNY`
- `listed_at <= delisted_at`

实现细节：

- `instrument_id` **不是单独落库字段**，而是通过 `StockInfoRecord.instrument_id` 动态拼成：
  - `SSE -> 600519.SH`
  - `SZSE -> 000001.SZ`

### 3.3 `trading_calendar`

用途：保存交易日历。

对应代码：

- SQL：`sql/001_initial_schema.sql`
- 模型：`TradingCalendarRecord`
- Repository：`TradingCalendarRepository`

核心字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer | 主键 |
| `market` | text | 当前固定为 `CN` |
| `trade_date` | text | 日期 |
| `is_open` | integer | `0/1` |
| `created_at` / `updated_at` | text | 创建/更新时间 |

约束：

- `(market, trade_date)` 唯一

实现细节：

- `TradingCalendarPipeline` 会对自然日区间逐天展开。
- adapter 只返回开市日集合；pipeline 再补出 `is_open = 0` 的自然日。

### 3.4 `stock_daily`

用途：保存标准层日线行情。

对应代码：

- SQL：`sql/001_initial_schema.sql`
- 模型：`StockDailyRecord`
- Repository：`StockDailyRepository`
- 读取服务：`StockDailyService`

核心字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer | 主键 |
| `stock_id` | integer | 引用 `stock_info.id` |
| `trade_date` | text | 交易日 |
| `open` / `high` / `low` / `close` | integer | 价格按“分”存储 |
| `volume` | integer | 成交量，按股存储 |
| `amount` | integer | 成交额，当前接入时量化为整数金额后落库 |
| `turnover` | integer / null | 换手率按原值乘 `10000` 后落库 |
| `ingestion_batch_id` | integer | 引用 `ingestion_batch.id` |
| `ingested_at` / `updated_at` | text | 入库/更新时间 |

约束：

- `(stock_id, trade_date)` 唯一
- `open/high/low/close > 0`
- `high >= open/close/low`
- `low <= open/close`
- `volume >= 0`
- `turnover >= 0` 或为空

当前口径：

- 接入来源为 `AkshareDailyQuoteAdapter`
- 抓取调用固定为 `stock_zh_a_hist_tx(..., adjust="qfq")`
- 因此当前 `stock_daily` 实际承接的是**前复权日线口径**，而不是原始不复权价格

### 3.5 `indicators`

用途：保存指标定义元数据，并记录物化进度。

对应代码：

- SQL：`sql/002_indicators.sql`、`sql/003_initial_builtin_indicator.sql`
- 模型：`IndicatorRecord`
- Repository：`IndicatorRepository`
- 运行时映射：`IndicatorDefinition`

核心字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer | 主键 |
| `indicator_id` | text | 指标逻辑标识 |
| `version` | text | 版本，默认 `v1` |
| `indicator_name` | text | 展示名称 |
| `category` | text | `trend` / `momentum` / `volatility` / `volume` / `custom` |
| `compute_ref` | text | `module.path:ClassName` |
| `params` | text | JSON 对象 |
| `output_columns` | text | JSON 字符串数组 |
| `storage_key` | text | Parquet 数据集相对路径 |
| `description` | text | 描述 |
| `status` | text | `active` / `deprecated` / `disabled` |
| `last_materialized_date` | text | 最近一次成功物化到的交易日 |
| `attach_kline` | integer | 预留字段，当前主流程未使用 |
| `created_at` / `updated_at` | text | 创建/更新时间 |

约束：

- `(indicator_id, version)` 唯一
- `storage_key` 唯一

当前内置初始化内容：

- 均线：`ma_5_10_20_30_60_120`
- MACD：`macd_12_26_9`
- ATR：`atr_14`
- 布林带：`boll_20_2`

### 3.6 `factors` 与 `strategies`

用途：这两张表已经建表，但目前只算**预留/半落地模型**。

对应代码：

- SQL：`sql/004_factors.sql`、`sql/005_strategies.sql`
- Python 侧只有部分类型：
  - `FactorMetaRecord`
  - `StrategyMeta`（注意这是 dataclass，不是 repository record）

当前状态：

- `RepositorySession` 还没有 `factor` / `strategy` repository
- 没有 controller、service、CLI 去维护这两张表
- 因此它们不能算已经进入主流程

- `category`
- `compute_ref`
- `params`
- `output_columns`
- `storage_key`
- `description`

### 4.2 `IndicatorSpec`

## 7. 当前关键关系

```text
ingestion_batch 1 --- N stock_daily
stock_info 1 --- N stock_daily
stock_info + exchange/symbol -> instrument_id（运行时派生）
indicators 1 --- N parquet year partitions（按 storage_key 组织）
```

补充说明：

- `trading_calendar` 当前没有用外键直接连到 `stock_daily`，但被 pipeline 和回测/研究预处理逻辑使用。
- 指标值不落 SQLite 表，而是落到 `data/indicators/{storage_key}/year=YYYY/data.parquet`。

## 8. 当前统一约定

### 8.1 主键与唯一键

- 表主键统一是 `id INTEGER`
- 业务唯一性通过自然键表达，例如：
  - `stock_info`：`(market, exchange, symbol)`
  - `trading_calendar`：`(market, trade_date)`
  - `stock_daily`：`(stock_id, trade_date)`
  - `indicators`：`(indicator_id, version)` 与 `storage_key`

### 8.2 时间字段

SQLite 中日期/时间当前都以 `TEXT` 形式持久化，代码侧再解析成：

- `date`
- `datetime`

格式约定由 `modules/utils/time_util.py` 统一处理。

### 8.3 数值存储

- 价格：整数分
- 成交量：整数股
- 成交额：整数金额
- 换手率：原值 × `10000`

### 8.4 派生字段

- `instrument_id` 为派生字段，不落库
- 指标数据集路径由 `storage_key` 派生，不单独建路径表

## 9. 当前没有落地的对象

以下概念在文档里可以讨论，但当前代码并未形成正式模型：

- 研究数据集规格表
- 因子值总表 / 标签总表
- 因子评估结果表
- 选股结果表
- 完整回测结果表
- 订单 / 成交 / 持仓 / 账户表

## 10. 当前结论

当前项目真正稳定的数据模型主线是：

1. `ingestion_batch + stock_info + trading_calendar + stock_daily`
2. `indicators` 元数据 + Parquet 指标分区
3. `StockDailyData / Context / Signal` 这类研究与策略运行时对象

而 `factors`、`strategies`、`backtest` 仍处于预留或半落地状态，不应再被描述为已经稳定完备的核心实体。
