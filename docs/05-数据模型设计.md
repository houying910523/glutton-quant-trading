# 数据模型设计

## 1. 目标

这份文档只解决首版 MVP 的数据模型问题，服务于以下闭环：

```text
数据接入 -> 数据标准化 -> 数据存储 -> 因子/标签研究 -> 策略信号 -> 回测
```

目标很明确：

- 让研究、信号生成、回测使用同一套数据对象
- 让因子、标签、信号这些研究概念能在模型边界上保持分离
- 让 A 股示例能落地，但模型本身不被 A 股写死
- 只设计首版真正需要的数据，不为未来可能的实盘和多市场提前堆模型

## 2. 设计边界

首版数据模型只覆盖以下对象：

- 标的基础信息
- 交易日历
- K 线行情
- 策略输入数据集
- 回测输出结果

这里要特别说明：

首版只覆盖**正式落库的核心对象**。

因子值、未来表现标签、因子评估结果、选股结果虽然在研究概念上存在，但当前阶段先不强制抽象成通用实体表。

首版明确不做：

- Tick 级逐笔成交
- L2 盘口
- 通用 `factor_value` / `future_label` / `factor_evaluation` 关系表
- 订单、成交、账户、持仓对象
- 新闻、研报、舆情等非结构化数据
- 实时流式事件总线

## 3. 统一建模原则

### 3.1 主键统一规则

所有实体表主键统一使用 `id INTEGER`。

外部引用某个实体主键时，统一使用 `xxx_id INTEGER`。

业务身份不再直接塞进主键，而是通过业务唯一键表达，例如：

- `stock` 用 `(market, exchange, symbol)` 唯一
- `trading_calendar` 用 `(market, trade_date)` 唯一
- `daily_quote` 用 `(stock_id, trade_date)` 唯一

原因：

- 数据库主键统一为整数后，外键更短，表连接和索引实现更直接
- 业务身份仍然保留在唯一键中，不依赖数据库内部行号之外的隐式约束

### 3.2 时间字段必须语义明确

所有时间字段必须显式区分：

- `trade_date`：交易日，按市场日历定义
- `bar_time`：K 线对应时间点
- `listed_at` / `delisted_at`：上市/退市时间
- `ingested_at`：数据进入系统时间
- `updated_at`：记录最后更新时间

首版统一使用 `Asia/Shanghai` 作为 A 股示例时区，但字段语义不与时区强绑定。

### 3.3 原始值和标准值分层

原始数据不直接进入策略层。

每条数据至少经历两层：

- 原始层：尽量保留外部字段和原始值
- 标准层：转换成内部统一模型

### 3.4 数据口径显式化

影响回测结果的关键口径必须可追踪：

- 成分股是否按当期快照回放
- 缺失值如何处理

这些口径不能藏在代码里，必须作为数据集元信息存在。

### 3.5 概念对象与落库对象分离

从研究方法论看，至少有 4 类对象需要被区分：

- 历史行情
- 因子值
- 未来表现标签
- 选股结果

但“需要区分”不等于“首版都要建成正式核心表”。

当前设计的取舍是：

- 历史行情作为标准层正式实体落库
- 因子值和未来标签优先作为研究过程中的中间对象、特征列或导出产物存在
- 选股结果优先体现在策略输出和回测明细中，而不是先建一套独立交易结果模型

这样做的原因很简单：

- 先保证研究边界清晰
- 再避免一开始就把数据模型做成宽而重的平台

## 4. 核心实体

## 4.1 Stock

表示一个可研究、可回测的交易标的。

### 字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | integer | 是 | 数据库主键 |
| `market` | string | 是 | 市场，例如 `CN` |
| `exchange` | string | 是 | 交易所，例如 `SSE`、`SZSE` |
| `symbol` | string | 是 | 交易代码，例如 `600519` |
| `ticker` | string | 否 | 显示代码，可与 `symbol` 相同 |
| `name` | string | 是 | 标的名称 |
| `asset_type` | string | 是 | 首版固定支持 `stock` |
| `currency` | string | 是 | 首版 A 股示例固定为 `CNY` |
| `lot_size` | integer | 是 | 最小交易单位，A 股常见为 `100` |
| `listed_at` | date | 否 | 上市日期 |
| `delisted_at` | date | 否 | 退市日期 |
| `status` | string | 是 | `active`、`delisted` |
| `created_at` | datetime | 是 | 首次写入时间 |
| `updated_at` | datetime | 是 | 最后更新时间 |

### 约束

- `market + exchange + symbol` 唯一
- 首版不支持一个 `(market, exchange, symbol)` 对应多个交易币种

## 4.2 TradingCalendar

表示日频研究和回测使用的交易日历。

### 字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | integer | 是 | 数据库主键 |
| `market` | string | 是 | 市场，例如 `CN` |
| `trade_date` | date | 是 | 交易日 |
| `is_open` | boolean | 是 | 是否开市 |
| `created_at` | datetime | 是 | 首次写入时间 |
| `updated_at` | datetime | 是 | 最后更新时间 |

### 约束

- `market + trade_date` 唯一
- 非交易日也允许落表，便于调度和回测统一判断
- 首版只表达“这一天是否开市”，不表达盘中 session 细节

## 4.3 DailyQuote

首版最核心行情对象，支持日频研究与回测。

### 字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | integer | 是 | 数据库主键 |
| `stock_id` | integer | 是 | 引用 `stock.id` |
| `trade_date` | date | 是 | 交易日 |
| `open` | decimal(18,2) | 是 | 开盘价 |
| `high` | decimal(18,2) | 是 | 最高价 |
| `low` | decimal(18,2) | 是 | 最低价 |
| `close` | decimal(18,2) | 是 | 收盘价 |
| `volume` | decimal(24,6) | 是 | 成交量 |
| `turnover` | decimal(24,6) | 否 | 成交额 |
| `ingestion_batch_id` | integer | 是 | 最后一次写入这条记录的批次 ID |
| `ingested_at` | datetime | 是 | 入库时间 |
| `updated_at` | datetime | 是 | 最后更新时间 |

### 约束

- `stock_id + trade_date` 唯一
- 首版 A 股示例下，OHLC 价格精度固定为两位小数
- `ingestion_batch_id` 用于把标准记录追溯回具体抓取批次

## 4.4 ResearchDatasetSpec

表示一份可复现的研究/回测输入数据集规格。

### 字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | integer | 是 | 数据库主键 |
| `name` | string | 是 | 数据集名称 |
| `market` | string | 是 | 市场 |
| `universe_definition` | json | 是 | 标的池定义 |
| `bar_frequency` | string | 是 | 首版固定 `1d` |
| `start_date` | date | 是 | 起始日期 |
| `end_date` | date | 是 | 结束日期 |
| `filters` | json | 否 | 上市天数、成交额阈值等过滤条件 |
| `feature_columns` | json | 否 | 需要暴露给策略的字段列表 |
| `version` | integer | 是 | 版本号 |
| `created_at` | datetime | 是 | 创建时间 |

### 约束

- `name + version` 唯一
- 同名数据集修改口径时必须升版本，不覆盖原记录

## 4.5 BacktestResult

表示一次完整回测的输入摘要与输出结果。

### 字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | integer | 是 | 数据库主键 |
| `strategy_id` | string | 是 | 策略标识 |
| `strategy_version` | string | 是 | 策略版本 |
| `dataset_spec_id` | integer | 是 | 引用 `research_dataset_spec.id` |
| `params` | json | 是 | 策略参数 |
| `started_at` | datetime | 是 | 开始时间 |
| `finished_at` | datetime | 否 | 结束时间 |
| `status` | string | 是 | `running`、`success`、`failed` |
| `error_message` | string | 否 | 失败原因 |
| `total_return` | decimal(18,8) | 是 | 总收益率 |
| `annual_return` | decimal(18,8) | 否 | 年化收益 |
| `max_drawdown` | decimal(18,8) | 是 | 最大回撤 |
| `sharpe` | decimal(18,8) | 否 | 夏普比率 |
| `trade_count` | integer | 是 | 交易次数 |
| `win_rate` | decimal(18,8) | 否 | 胜率 |
| `created_at` | datetime | 是 | 生成时间 |

### 约束

- 首版允许 `status = running` 时指标字段为空
- 如果后续出现大规模异步任务管理、分步计算或多版本指标快照，再考虑拆回 `run` 和 `metric`

## 5. 实体关系

```text
Stock 1 --- N DailyQuote
TradingCalendar 1 --- N DailyQuote
ResearchDatasetSpec 1 --- N BacktestResult
```

## 6. 首版标准字段约定

为了避免字段命名混乱，首版统一采用以下规则：

- ID 类字段统一使用 `_id`
- 实体主键字段统一使用 `id`
- 日期统一使用 `_date`
- 时间统一使用 `_at`
- 布尔字段统一使用 `is_` 开头
- 金额和价格统一使用十进制定点数，不用浮点
- JSON 字段只用于配置类、口径类对象，不用于高频行情明细

## 7. 存储分层

首版数据至少分三层：

### 7.1 Raw Layer

存原始响应或原始文件，目的是可追溯和可重放。

建议对象：

- 原始 API 响应
- 原始 CSV/Parquet 文件
- 原始抓取批次元信息

### 7.2 Standard Layer

存统一后的核心表，是策略和回测直接读取的主要来源。

建议对象：

- `stock`
- `trading_calendar`
- `daily_quote`

### 7.3 Serving Layer

存面向研究和回测的投影视图或导出数据集。

建议对象：

- `research_dataset_spec`
- `backtest_result`
- 按策略读取习惯投影后的宽表或数据切片
- 预计算的因子值快照或研究宽表
- 未来表现标签切片
- 因子评估结果、选股结果和研究报告导出物

## 8. 首版默认决策

为了避免实现时再次悬空，首版直接锁定以下默认值：

- 默认频率：`1d`
- 默认市场示例：A 股
- 默认资产类型：`stock`
- 默认币种：`CNY`
- 默认研究对象：股票日线和相关参考数据
- 默认不支持 tick、盘口和实时流

## 9. 实现顺序建议

按最小闭环，数据模型落地顺序应当是：

1. `Stock`
2. `TradingCalendar`
3. `DailyQuote`
4. `ResearchDatasetSpec`
5. `BacktestResult`

这个顺序的目的很直接：

- 先让数据能被唯一识别
- 再让时间和行情能被正确组织
- 最后再定义回测输入输出

## 10. 对后续实现的约束

- 不允许策略层直接读取原始层数据
- 不允许同一字段在不同表里使用不同命名
- 不允许先做订单和账户模型，再反推研究数据模型
