# 首版数据接入与标准化存储详细设计

## 1. 文档目标

这份文档以当前仓库代码为准，说明首版数据接入与标准化存储已经如何实现。

它回答的不是“理想上应该怎么做”，而是：

- 当前程序化接入到底接了哪些数据
- 当前模块怎么拆
- 当前 SQLite 表结构长什么样
- 当前批处理任务支持哪些运行方式
- 哪些能力已经实现，哪些明确还没做

## 2. 当前实现范围

当前代码只覆盖 3 类标准数据：

1. `stock`
2. `trading_calendar`
3. `daily_quote`

当前实现不覆盖：

- `research_dataset_spec`
- `backtest_result`
- `data_quality_issue` 正式表
- Serving Layer
- 多数据源仲裁
- 实时流式同步

## 3. 当前技术栈

当前实现已经落地的技术栈如下：

| 类别 | 当前实现 |
| --- | --- |
| 运行时 | Python 3.12 |
| 包管理 | `uv` |
| CLI | `Typer` |
| 数据模型 | `Pydantic 2` |
| 数据库 | SQLite |
| 原始层 | 本地文件系统 |
| 数据源 | `AkShare` |
| 测试 | `pytest` + `unittest` 风格测试 |

当前代码没有接入 `Tushare Pro`。

## 4. 当前目录与模块拆分

当前实现主要集中在以下目录：

```text
modules/
  config.py
  datasource/
    adaptors/
    jobs/
    pipeline/
    shared/
  repositories/
sql/
  001_initial_schema.sql
```

职责划分如下：

### `modules/config.py`

提供默认路径：

- SQLite 文件：`data/system/glutton.db`
- Raw 根目录：`data/raw`

### `modules/repositories/`

负责：

- SQLite 连接
- schema 初始化
- `ingestion_batch / stock / trading_calendar / daily_quote` 的读写

### `modules/datasource/adaptors/`

负责：

- 调用 AkShare
- 把返回结果转换成 `StockRecord`、交易日字符串、`DailyQuoteRecord`

### `modules/datasource/pipeline/services/`

负责：

- 创建批次
- 执行同步流程
- upsert 标准表
- 记录批次统计信息

### `modules/datasource/jobs/`

负责：

- 暴露 CLI 命令入口
- 初始化 runtime、数据库和 raw store

## 5. 当前数据库实现

## 5.1 当前正式 schema

当前 SQL 脚本 [sql/001_initial_schema.sql](../sql/001_initial_schema.sql) 实际创建了 4 张正式表：

- `ingestion_batch`
- `stock`
- `trading_calendar`
- `daily_quote`

当前没有创建 `data_quality_issue`。

## 5.2 `ingestion_batch`

当前字段以代码实现为准，核心字段包括：

- `batch_key`
- `source_name`
- `resource_type`
- `sync_mode`
- `start_date`
- `end_date`
- `request_params`
- `status`
- `raw_count`
- `valid_count`
- `loaded_count`
- `rejected_count`
- `retry_count`
- `error_summary`

说明：

- 当前列名是 `raw_count / valid_count / loaded_count / rejected_count`
- 不是旧文档里那套 `row_count_raw / row_count_valid / ...`

## 5.3 `stock`

当前实现与设计基本一致：

- 业务唯一键：`(market, exchange, symbol)`
- 当前只支持 `SSE` / `SZSE`
- `asset_type` 固定为 `stock`
- `currency` 固定为 `CNY`

## 5.4 `trading_calendar`

当前实现：

- 业务唯一键：`(market, trade_date)`
- `is_open` 用 `0 / 1` 存储
- 支持把自然日期区间展开后整段入库

## 5.5 `daily_quote`

当前实现：

- 业务唯一键：`(stock_id, trade_date)`
- `open / high / low / close` 以整数分存储
- `volume` 以整数股存储
- `turnover` 以整数分存储
- 保留 `ingestion_batch_id` 追溯来源批次

## 6. 当前数据源与 adapter 实现

## 6.1 当前主数据源

当前程序化接入只实现了 `AkShare`。

代码位置：

- [modules/datasource/adaptors/akshare.py](../modules/datasource/adaptors/akshare.py)

`AdapterType` 虽然包含 `"tushare"`，但当前 factory 仍只支持 `"akshare"`。

## 6.2 当前 adapter 协议

当前实现不是通用 `SourceAdapter.fetch(request)` 模型，而是按资源拆成 3 个专用协议：

```python
class StockFetcher(Protocol):
    def fetch(self) -> list[StockRecord]: ...

class TradingCalendarFetcher(Protocol):
    def fetch(self, start_date: str, end_date: str) -> list[str]: ...

class StockDailyQuoteFetcher(Protocol):
    def fetch(
        self,
        symbol: str,
        start_date: str,
        end_date: str,
        stock_id: int,
        batch_id: int,
    ) -> list[DailyQuoteRecord]: ...
```

对应 factory 为：

- `create_stock_fetcher()`
- `create_trading_calendar_fetcher()`
- `create_stock_daily_quote_fetcher()`

## 6.3 `AkshareStockAdapter`

当前行为：

- 拉取上交所主板 A 股列表
- 拉取深交所 A 股列表
- 拉取上交所退市列表
- 拉取深交所退市列表
- 去重后转换成 `StockRecord`

当前标准化约定：

- 市场固定为 `CN`
- 上交所映射为 `SSE`
- 深交所映射为 `SZSE`
- 活跃 / 退市列表转换成 `active / delisted`
- `lot_size` 固定写 `100`

## 6.4 `AkshareTradingCalendarAdapter`

当前行为：

- 调 `tool_trade_date_hist_sina()`
- 读取开市日列表
- 返回开市日字符串列表

注意：

- 当前 adapter 的 `fetch(start_date, end_date)` 签名保留了日期参数
- 但当前实现内部并不依赖这两个参数过滤源数据
- 真正的日期范围展开逻辑在 pipeline 中完成

## 6.5 `AkshareDailyQuoteAdapter`

当前行为：

- 对单只股票调用 `stock_zh_a_hist_tx`
- 自动把 `600519` 这类 symbol 推断成 `sh600519 / sz000001`
- 把日线结果直接转换成 `DailyQuoteRecord`

当前约定：

- 单次抓取是“单股票、单区间”
- 不是“按交易日拉全市场”
- `stock_id` 和 `batch_id` 由 pipeline 注入

## 7. 当前 Raw Layer 实现

当前 Raw Layer 代码位于：

- [modules/datasource/pipeline/raw_store.py](../modules/datasource/pipeline/raw_store.py)

目录结构如下：

```text
data/raw/{source_name}/{resource_type}/ingest_date={yyyy-mm-dd}/ingestion_batch_key={batch_key}/
  manifest.json
```

当前主流程实际落盘的是：

- `manifest.json`

当前已经提供但尚未接入主流程的能力：

- `write_records_jsonl()`

也就是说：

- 当前 Raw Layer 已经有批次目录和 manifest
- 但默认流程还没有把源侧逐条记录写成 `records.jsonl`

## 8. 当前批次与 pipeline 实现

## 8.1 `BasePipeline`

当前基础流程位于：

- [modules/datasource/pipeline/services/base.py](../modules/datasource/pipeline/services/base.py)

主流程是：

```text
create_running_batch
-> write_manifest(status=running)
-> 执行具体资源的 _process()
-> complete_batch
-> write_manifest(status=success/failed)
```

当前批次创建时会写：

- `resource_type`
- `sync_mode`
- `start_date`
- `end_date`

当前 `request_params` 会保存为空字典。

这意味着当前实现保留了 `request_params` 字段，但还没有把 CLI 原始参数完整透传进去。

## 8.2 `StockPipeline`

当前行为：

- 调 `create_stock_fetcher()`
- 批量拉取股票列表
- 对 `stock` 做 upsert

当前补充行为：

- 如果数据库里已有同自然键记录且名称不同，会把该新记录加入 `rejected_records`
- 但当前代码仍会把这条记录放进 `accepted` 并参与 upsert

因此当前 `rejected_count` 更像统计信息，而不是硬拒绝。

## 8.3 `TradingCalendarPipeline`

当前行为：

- 要求批次里必须有 `start_date` 和 `end_date`
- 用 adapter 拉开市日集合
- 在 pipeline 内把整个自然日区间展开成 `TradingCalendarRecord`
- `trade_date in open_dates` 的日期写 `is_open = true`
- 其他日期写 `is_open = false`

注意：

- 当前 CLI 没有默认日期窗口逻辑
- 如果不给 `--start-date` 和 `--end-date`，当前实现会报错

## 8.4 `DailyQuotePipeline`

当前行为是“按股票增量续跑”。

具体流程：

1. 读取活跃股票列表
2. 可按 `stock_id` 或 `symbol` 过滤目标股票
3. 对每只股票查询本地最新已落库交易日
4. 若已存在历史，则从下一天继续
5. 若不存在历史，则从 `listed_at` 或默认的 `1991-01-01` 开始
6. 查询 `trading_calendar`，找到从起点到今天之间的开市日
7. 用最后一个开市日作为这只股票本次抓取终点
8. 逐股票调用 `AkshareDailyQuoteAdapter.fetch()`
9. upsert 到 `daily_quote`

当前没有实现的能力：

- 历史缺口校验
- 覆盖率告警
- 按交易日全市场抓取
- 自动重刷失败日期

## 9. 当前 CLI 实现

当前 3 个命令入口如下：

### `sync_stocks`

```bash
python -m modules.datasource.jobs.sync_stocks --adapter akshare
```

当前行为：

- 全量拉取股票清单
- 批次 `sync_mode = full`

### `sync_trading_calendar`

```bash
python -m modules.datasource.jobs.sync_trading_calendar --start-date 2024-01-01 --end-date 2024-12-31
```

当前行为：

- 必须显式提供 `start_date` 和 `end_date`
- 没有默认窗口

### `sync_daily_quotes`

```bash
python -m modules.datasource.jobs.sync_daily_quotes --symbol 600519
python -m modules.datasource.jobs.sync_daily_quotes --stock-id 1
```

当前行为：

- 默认 `sync_mode = incremental`
- 不支持直接传日期区间
- 依赖本地 `trading_calendar` 和 `stock` 已经准备好

## 10. 当前质量与校验策略

当前已经存在的校验主要来自两层：

### 1) `Pydantic` 模型校验

- `StockRecord` 校验上市/退市日期顺序
- `DailyQuoteRecord` 校验 OHLC、volume、turnover 合法性

### 2) SQLite 约束

- 唯一键约束
- 外键约束
- OHLC 关系约束
- 枚举值约束

当前尚未正式实现：

- 独立的 `data_quality_issue` 记录链路
- `warn/reject` 分级入库
- `daily_quote` 覆盖率阈值检查

## 11. 当前实现与早期设计的主要取舍

和更早期的详细设计相比，当前代码已经收敛成更简单的一版：

- 主数据源先只保留 `AkShare`
- adapter 不做统一万能接口，而是按资源拆专用协议
- 批处理任务先按“单股票增量抓日线”实现，不先做“按交易日全市场抓取”
- 先落 `ingestion_batch + stock + trading_calendar + daily_quote`
- 质量问题表和覆盖率告警先不进入正式链路
- 原始层先落 `manifest.json`，`records.jsonl` 能力预留但不强制接通

## 12. 当前文档结论

如果你要以当前代码为准理解首版数据底座，可以把它概括成：

> 一个基于 Python + SQLite + AkShare 的本地离线批处理实现，已经具备股票清单、交易日历和个股日线数据的批次化落库能力，但仍处于“先把主链路做通，再逐步补质量与回放能力”的阶段。
