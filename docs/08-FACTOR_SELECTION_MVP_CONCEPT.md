# 因子研究与选股系统 MVP 概念设计

## 1. 文档目的

本文档用于描述一个最小可行版本（MVP）的**因子研究与选股系统**的概念性设计。

该文档只保留抽象层设计，不绑定任何现有项目、技术栈、文件结构或实现细节，目的是供后续 agent 基于此继续展开：

- 方案设计
- 模块拆分
- 接口定义
- 数据结构设计
- 原型实现规划

## 2. 系统目标

该系统只解决三个问题：

1. 指标/因子挖掘
2. 指标/因子有效性验证
3. 基于有效因子进行选股

它是一个**离线研究型系统**，不是完整交易系统。

## 3. 系统定位

这是一个以历史日频数据为输入、以因子研究为核心、以选股结果为输出的研究系统。

它的重点是：

- 从历史数据中提取候选因子
- 判断哪些因子具有稳定的选股能力
- 将有效因子转换为可执行的选股结果

它不负责：

- 实盘交易
- 订单执行
- 风险执行
- 实时监控
- 账户管理

## 4. 系统边界

### 4.1 系统内

系统内部应覆盖以下能力：

- 历史数据标准化
- 因子生成
- 未来表现定义
- 因子有效性评估
- 选股逻辑生成
- 结果输出与研究沉淀

### 4.2 系统外

系统外部能力不属于本 MVP：

- 数据抓取系统
- 实时行情系统
- 交易执行系统
- 风控执行系统
- 调度系统
- 可视化平台型前端

## 5. 核心模块

MVP 只需要 6 个核心模块。

### 5.1 数据层

职责：

- 接收历史市场数据
- 将原始数据整理为统一、可计算的标准化数据对象
- 为因子计算和回测提供一致的数据输入

核心问题：

- 数据格式是否统一
- 时间维度是否对齐
- 标的维度是否可横向比较
- 数据是否可直接进入后续研究流程

输出：

- 标准化历史行情对象

### 5.2 因子层

职责：

- 从标准化历史行情中生成候选指标/因子
- 为每个时间点、每个标的计算对应的因子值

本质：

- 特征生成器

典型因子类别：

- 趋势类
- 动量类
- 波动率类
- 量价类
- 均值回归类
- 技术指标类

输出：

- 因子对象

### 5.3 标签层

职责：

- 定义因子评估所依据的未来表现目标
- 将“因子值”与“未来结果”建立可研究的对应关系

本质：

- 监督目标生成器

典型目标形式：

- 未来 N 日收益
- 未来超额收益
- 未来横截面收益排名
- 未来分组表现

输出：

- 未来表现对象

### 5.4 因子评估层

职责：

- 检验因子是否具备稳定的预测能力或选股能力
- 判断因子是偶然有效还是具有统计稳定性
- 为后续选股提供因子筛选依据

本质：

- 因子研究验证器

典型评估视角：

- 相关性
- 排名相关性
- 分组收益差异
- 多空收益表现
- 稳定性
- 覆盖率

输出：

- 因子有效性评价结果

### 5.5 选股层

职责：

- 将已验证有效的因子转化为选股规则
- 在每个决策时点输出股票池

本质：

- 从研究到决策的转换层

典型选股方式：

- 单因子排序选股
- 多因子加权打分选股
- 因子过滤 + 排名选股

输出：

- 选股结果对象

### 5.6 输出层

职责：

- 输出因子评估结果
- 输出选股结果
- 沉淀研究结论

本质：

- 结果表达层

典型输出形式：

- 研究报告
- 指标汇总表
- 因子表现对比表
- 每期选股结果
- 图表或可视化素材

## 6. 模块交互关系

系统主链路如下：

```text
历史数据
  → 数据标准化
  → 因子生成
  → 未来标签生成
  → 因子评估
  → 选出有效因子
  → 选股
  → 输出结果
```

如果从层次上看，可以抽象成三层：

```text
输入层：数据
分析层：因子 + 标签 + 评估
输出层：选股 + 报告
```

## 7. 核心对象模型

从概念上，系统只需要 4 类核心对象。

### 7.1 历史行情对象

表示某个时间点、某个标的的原始市场信息。

作用：

- 作为因子计算基础
- 作为未来表现计算基础

### 7.2 因子对象

表示某个时间点、某个标的的某个因子值。

作用：

- 描述标的在某个维度上的特征
- 参与横截面比较与因子评估

### 7.3 未来表现对象

表示某个时间点、某个标的在未来一段时间内的结果。

作用：

- 作为因子评估的目标变量

### 7.4 选股结果对象

表示某个决策时点最终被选中的标的集合。

作用：

- 作为研究系统的最终决策输出

## 8. 模块输入输出关系

### 数据层

- 输入：原始历史数据
- 输出：标准化历史行情对象

### 因子层

- 输入：标准化历史行情对象
- 输出：因子对象

### 标签层

- 输入：标准化历史行情对象
- 输出：未来表现对象

### 因子评估层

- 输入：因子对象 + 未来表现对象
- 输出：因子有效性评价结果

### 选股层

- 输入：有效因子 + 当前时点因子值
- 输出：选股结果对象

### 输出层

- 输入：评估结果 + 选股结果
- 输出：研究报告与结果材料

## 9. 系统最小闭环

一个最小闭环必须满足：

1. 能接收历史日频数据
2. 能生成候选因子
3. 能定义未来表现标签
4. 能评价因子有效性
5. 能基于有效因子选出标的
6. 能输出可解释结果

只要这 6 步能跑通，就已经构成 MVP。

## 10. 设计原则

### 10.1 数据、因子、标签分离

历史数据、因子值、未来表现是三个不同层次的对象，不能混在一起设计。

### 10.2 评估与选股分离

“因子有没有用” 和 “因子怎么用于选股” 是两件事。

应先评估，再决定是否纳入选股逻辑。

### 10.3 单因子与多因子分离

应优先验证单因子有效性，再考虑多因子合成。

MVP 阶段不宜一开始就进入复杂模型。

### 10.4 结果必须可解释

系统输出不仅要有结果，还应能回答：

- 为什么认为某个因子有效
- 为什么某个标的被选中

### 10.5 研究系统优先于交易系统

MVP 阶段的重点是建立稳定的研究闭环，而不是提前引入交易、风控、调度等非核心能力。

## 11. 典型研究流程

一个典型的使用流程可以抽象为：

1. 输入一批历史日频数据
2. 生成一组候选因子
3. 定义未来表现标签
4. 对每个因子做有效性评估
5. 筛选出有效因子
6. 形成单因子或多因子选股规则
7. 输出每期股票池与研究结论

## 12. 下游方案设计建议

后续 agent 在基于本概念文档展开方案设计时，建议至少继续补全以下内容：

1. 模块级职责拆解
2. 数据对象结构定义
3. 因子评估方法设计
4. 选股规则定义方式
5. 研究结果输出规范
6. MVP 与后续演进版本的边界

## 13. 一句话总结

这个 MVP 可以被概括为：

> 一个以历史日频数据为输入、以因子研究为核心、以因子有效性验证为依据、最终输出股票池的离线研究系统。
