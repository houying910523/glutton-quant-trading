# 策略接口与回测接口设计

## 1. 文档目的

这份文档以当前代码为准，整理 `Factor`、`Filter`、`Selection`、`Strategy`、`Backtest` 之间的真实边界。

基准文件：

- `modules/core/`
- `modules/factors/`
- `modules/filters/`
- `modules/research/selection.py`
- `modules/strategies/`
- `modules/backtest/`

它回答两个问题：

1. 当前策略链路已经实现到哪一步
2. 当前各层接口在代码里到底长什么样

## 2. 当前代码状态

当前与这条主线直接相关的代码状态是：

- `modules/factors/` 已经有 `BoxConsolidationMatchFactor`
- `modules/filters/` 已经有 `main_board`、`turnover_rate`、`box_consolidation`
- `modules/research/selection.py` 已经能从 SQLite 读取最近 120 天日线并串联 Filter
- `modules/strategies/` 已经有决策式 `BaseStrategy` 协议、`StrategyDecision` / `TargetPosition` / `Signal` / `StrategyMeta` 模型，以及一个具体策略 `FactorScoreStrategy`
- `modules/backtest/` 已经补出输入输出模型、调仓日调度器、分析器与 runner 骨架，并且 `BacktestEngine.run()` 已有 MVP：固定调仓、`strategy.decide()`、`next_open` 成交、收盘估值、净值曲线、订单/成交记录

因此，当前仓库的真实状态是：

> 研究筛选与策略原型已经落地；回测最小执行闭环已经落地，但 A 股交易约束与闭合交易记录仍未补齐。

## 3. 当前链路怎么分层

### 3.1 标准层数据读取

由 `StockDailyService.load_stock_daily()` 负责：

- 从 `stock_daily + stock_info` 读取日线
- 产出 `trade_date + instrument_id + columns...` 的 `polars.DataFrame`
- 可按 `instruments`、`columns`、`optional` 过滤

### 3.2 `StockDailyData` / `Context`

位置：`modules/core/context.py`

当前研究和策略层共享两个核心运行时对象：

```python
@dataclass(frozen=True)
class StockDailyData:
    instrument_id: str
    data: pl.DataFrame

@dataclass(frozen=True)
class Context:
    start_date: str
    end_date: str
    stock_daily_data: list[StockDailyData]
    stocks: dict[str, StockInfoRecord]
```

它们是当前“把标准层数据喂给因子/策略”的最小桥梁。

### 3.3 `Factor`

位置：`modules/core/factor.py`

当前抽象：

```python
class Factor(ABC):
    def inputs(self) -> list[str]: ...
    def compute(self, context: Context) -> dict[str, pl.DataFrame]: ...
    def matches(self, stock_daily_data: StockDailyData) -> bool: ...
```

职责：

- 声明依赖哪些输入列
- 在 `Context` 上计算每只股票的因子结果
- 或对单只股票直接给出是否匹配

当前已落地示例：

- `BoxConsolidationMatchFactor`

### 3.4 `Filter`

位置：`modules/filters/filter.py`

当前抽象：

```python
class Filter(Protocol):
    name: str
    params_schema: list[ParamsProperty]

    def dependencies(self) -> list[str]:
        return []

    def filter(self, data: list[StockDailyData]) -> list[StockDailyData]: ...
```

职责：

- 接收多只股票的历史切片
- 返回筛选后的股票集合

当前已实现 Filter：

- `MainBoardFilter`
- `TurnoverRateFilter`
- `BoxConsolidationFilter`

### 3.5 `Selection`

位置：`modules/research/selection.py`

当前 `Selection.run(filters, optional=False)` 的行为是：

1. 读取最近 `LOOKBACK_DAYS = 120` 天日线
2. 按 `instrument_id` 分组成 `list[StockDailyData]`
3. 依次执行传入的 `Filter`
4. 返回筛选后的股票切片列表

也就是说，当前项目里的“研究选股”已经不是纯概念，而是能真正串起：

```text
SQLite 日线 -> StockDailyData -> Filter 链 -> 结果股票集合
```

## 4. 当前策略接口

### 4.1 `BaseStrategy`

位置：`modules/strategies/base.py`

当前 `BaseStrategy` 已经切换成决策式协议：

```python
class BaseStrategy(Protocol):
    meta: StrategyMeta

    def decide(
        self,
        context: Context,
        portfolio_state: PortfolioState,
    ) -> StrategyDecision: ...
```

配套模型位于：`modules/strategies/models.py`

- `TargetPosition`
- `StrategyDecision`

`BaseStrategy` 作为统一策略核心接口。

### 4.2 `Signal`

位置：`modules/strategies/models.py`

当前字段：

- `symbol`
- `direction`
- `signal_type`
- `price`
- `volume`
- `reason`

`Signal` 位于模型层，可用于订单/信号表达。

### 4.3 `StrategyMeta`

## 5. 当前唯一具体策略：`FactorScoreStrategy`

位置：`modules/strategies/factor_score_strategy.py`

### 5.1 当前行为

`FactorScoreStrategy` 接受：

- `meta: StrategyMeta`
- `factors: list[Factor]`
- `factor_weights: dict[str, float]`
- `top_n_pct: float`

执行流程：

1. 遍历每个 `Factor`
2. 调用 `factor.compute(context)` 得到各股票因子序列
3. 每个因子只取最新一行 `factor_value`
4. 对因子列做去极值 `winsorize`
5. 对因子列做标准化 `standardize`
6. 按权重汇总成 `score`
7. 取分位数最高的股票作为目标持仓
8. 返回 `StrategyDecision(as_of_date, targets, close_missing_positions=True)`

### 5.2 当前边界

它已经说明两件事：

- 当前策略层已经收口到“输入 `Context + PortfolioState`、输出 `StrategyDecision`”
- 目标持仓解释逻辑仍然写在策略内部，而不是独立组合层

### 5.3 当前限制

- 当前 `decide()` 还没有真正使用 `portfolio_state` 做仓位差分或执行约束判断
- 策略直接输出 `StrategyDecision`
- 当前策略仍然把目标持仓解释逻辑写在策略内，而不是独立组合层
- 还没有闭合交易记录与更复杂的组合控制

## 6. 当前回测层状态

位置：`modules/backtest/`

当前已经有下面这些实现：

- `models.py`：`BacktestConfig`、`PortfolioState`、`BacktestResult`、`BacktestSummary` 等最小模型
- `scheduler.py`：`RebalanceScheduler`，支持 `daily` / `weekly` / `monthly`
- `engine.py`：已能完成调仓日生成、`Context` 构造、`strategy.decide()`、`next_open` 成交、组合状态推进、收盘估值、订单/成交记录输出
- `analyzer.py`：已能从 `equity_curve` 推导收益、波动、夏普、最大回撤、月度/年度收益摘要
- `runner.py`：统一组织 `engine.run()` 与 `analyzer.analyze()`

这意味着：

- 当前仓库已经具备可运行的最小回测闭环
- `BacktestEngine.run()` 已实现最小执行流
- 闭合交易生成、停牌处理、涨跌停细化和更复杂的组合控制还没有补齐

## 7. 当前推荐的边界表述

如果只描述当前代码，最准确的说法应该是：

### 7.1 因子层

负责：

- 基于 `Context` 计算特征
- 输出每只股票的时间序列结果

不负责：

- 直接落库到 SQLite
- 直接做成交解释

### 7.2 过滤层

负责：

- 基于 `list[StockDailyData]` 做集合裁剪

不负责：

- 组合构建
- 收益计算

### 7.3 选股层

负责：

- 从 SQLite 拉最近窗口数据
- 分组后串联 `Filter`

不负责：

- 信号收益回放
- 交易成本计算

### 7.4 策略层

当前已开始负责：

- 因子读取与合成打分
- 目标持仓解释
- 产出 `StrategyDecision`

### 7.5 回测层

当前已经负责：

- 定义回测输入输出模型
- 调仓日调度
- `Context` 构造辅助
- 基于 `BaseStrategy.decide()` 的回测执行主流程
- `next_open` 成交模拟
- 组合状态推进
- 收盘净值回放
- 订单 / 成交记录输出
- 结果分析入口

当前还没有负责：

- 更完整的 A 股执行约束细节（停牌、涨跌停细化、更多市场规则）
- 闭合交易生成
- 更复杂的组合与风控约束

## 8. 建议的下一步收口方向

结合当前代码现状，下一步应继续补齐下面几件事：

1. 让 `FactorScoreStrategy.decide()` 正式使用 `portfolio_state` 做仓位差分与约束判断
2. 明确 `StrategyDecision` 到订单/成交的转换规则
3. 明确 `Signal` 的定位与使用场景
4. 补齐停牌、涨跌停细化和更多市场规则
5. 生成 `TradeRecord` 等闭合交易结果

## 9. 当前结论

当前仓库在“策略与回测”这条线上的真实进度是：

- `Factor`、`Filter`、`Selection` 已经能跑研究筛选链路
- `FactorScoreStrategy` 已经切到 `BaseStrategy.decide()` 并输出 `StrategyDecision`
- `modules/backtest/` 已经补出最小回测闭环：固定调仓、`next_open` 成交、收盘估值、净值曲线、订单/成交记录，并已加入 A 股 `T+1`、整手买入和一字涨跌停的保守约束

因此，当前最应该推进的不是继续扩展理想化接口，而是继续把停牌、交易闭合与组合控制补完整。
