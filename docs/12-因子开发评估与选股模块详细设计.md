# 因子开发评估与选股模块详细设计

## 1. 文档目的

这份文档把 [09-FACTOR_SELECTION_MVP_CONCEPT](./09-FACTOR_SELECTION_MVP_CONCEPT.md) 的概念稿收敛成实现级设计，回答 4 个问题：

1. 首版因子开发模块必须具备哪些能力
2. 首版因子评估和选股模块必须具备哪些能力
3. 这些模块在代码里应该如何按面向对象方式拆分
4. 它们如何与 [11-策略与回测模块功能详细设计](./11-策略与回测模块功能详细设计.md) 对接

这份文档不替代 `09`，而是把 `09` 里的“因子 -> 标签 -> 评估 -> 选股”链路收成 Python 落地设计。

## 2. 在整体链路中的位置

当前更合理的实现顺序是：

```text
历史数据
-> 因子开发
-> 未来标签
-> 因子评估
-> 基于因子的选股
-> 把选股规则封装成策略
-> 回测
```

所以这份设计优先解决的是：

- 因子怎么开发
- 因子怎么管理
- 因子怎么评估
- 因子怎么变成选股结果

策略和回测只是它的下游。

## 3. 当前约束

这份设计以当前仓库已有事实为前提：

- 数据底座当前只正式覆盖 `stock`、`trading_calendar`、`daily_quote`
- 当前数据频率只有 `1d`
- 当前研究主线还未开始编码
- 当前还没有正式的 `research_dataset_spec`、`factor_value`、`future_label`、`factor_evaluation` 表
- 当前策略接口已经收敛到 DataFrame-first 的方向

因此首版研究模块必须遵守两个现实约束：

1. 研究中间产物优先作为 DataFrame 和导出文件存在，不急着建正式表
2. 接口要优先服务因子研究效率，而不是先做平台化管理后台

## 4. 非目标

首版明确不做：

- 因子管理 Web 平台
- 因子 CRUD 后台
- 因子在线实时计算服务
- 自动化调参平台
- 通用机器学习训练框架
- 大规模分布式因子搜索

一句话说：

首版做的是**因子开发运行时 + 轻量管理能力**，不是**因子管理平台**。

## 5. 首版必须具备的能力

首版因子研究与选股模块至少要具备以下能力：

1. 能基于统一 DataFrame 计算单个因子
2. 能把多个因子结果对齐、拼接成研究宽表
3. 能以轻量标签定义描述未来结果，并与因子结果对齐
4. 能对单因子做最小有效性评估
5. 能把一个或多个因子转成选股分数和入选列表
6. 能导出因子值、标签值、评估结果和选股结果
7. 能把选股结果平滑对接到策略接口
8. 能管理因子的身份、版本、默认参数和依赖列

## 6. 设计原则

## 6.1 DataFrame First

因子、轻量标签定义、评估和选股这条主链路，首版统一采用 `pandas.DataFrame` 作为公开输入输出格式。

原因很直接：

- 方便复用 `pandas`、`qlib`、技术指标库
- 更适合横截面排序和 rolling/groupby
- 比逐条对象回调更贴合日频因子研究

## 6.2 轻量管理，不做平台

“管理”只收敛到下面这些能力：

- 因子元信息
- 因子版本
- 因子默认参数
- 因子依赖列
- 因子清单查询

不延伸到：

- 审批流
- Web 管理台
- 权限系统

## 6.3 因子、标签、选股、策略边界分离

为避免后面再次混在一起，首版必须保持：

- 因子：回答“看什么特征”
- 轻量标签定义：回答“拿什么未来结果做验证”
- 评估：回答“这个因子有没有用”
- 选股：回答“怎么把一个或多个因子转成入选结果”
- 策略：回答“怎么把选股结果放进调仓和回测流程”

## 7. 模块拆分建议

首版建议在 `modules/research/` 下拆成以下最小结构：

```text
modules/research/
  __init__.py
  factors/
    __init__.py
    base.py
    models.py
    catalog.py
  validation/
    __init__.py
    models.py
    service.py
  selection/
    __init__.py
    base.py
    models.py
```

职责如下：

- `factors/`：因子接口、元信息和轻量目录管理
- `validation/`：轻量标签定义、标签构造和因子评估服务
- `selection/`：基于一个或多个因子的打分与选股

首版不建议再拆：

- `artifacts.py`
- `registry_db.py`
- `pipeline.py`
- `reporting/`

这些职责可以先收口在 `service.py` 或研究脚本里。

## 8. 首版必须稳定的公开接口

重新审查后，研究侧真正需要稳定下来的公开接口只有 3 个：

1. `Factor`
2. `FactorEvaluator`
3. `Selector`

它们分别对应：

- 因子开发边界
- 因子有效性评估边界
- 因子到选股的转换边界

## 9. 因子模块设计

## 9.1 核心对象

```python
from __future__ import annotations

from abc import ABC, abstractmethod
from dataclasses import dataclass
from datetime import date
from typing import Any, Literal

import pandas as pd
from pydantic import BaseModel, ConfigDict, Field

from modules.engine.strategies.models import DatasetSpec


class FactorDataRequirement(BaseModel):
    model_config = ConfigDict(extra="forbid")

    required_history_bars: int = 0
    required_columns: list[str] = Field(default_factory=list)


class FactorManifest(BaseModel):
    model_config = ConfigDict(extra="forbid")

    factor_id: str
    factor_name: str
    version: str
    description: str | None = None
    default_params: dict[str, Any]
    data_requirement: FactorDataRequirement
    output_column: str


@dataclass(slots=True)
class FactorInput:
    dataset_spec: DatasetSpec
    frame: pd.DataFrame
    params: dict[str, Any]


@dataclass(slots=True)
class FactorOutput:
    factor_id: str
    factor_version: str
    frame: pd.DataFrame


class Factor(ABC):
    @abstractmethod
    def manifest(self) -> FactorManifest: ...

    @abstractmethod
    def validate_params(self, params: dict[str, Any]) -> None: ...

    @abstractmethod
    def compute(self, input: FactorInput) -> FactorOutput: ...
```

## 9.2 因子输入输出语义

### `FactorInput.frame`

表示一份研究期内的统一历史长表。

至少应包含：

- `trade_date`
- `instrument_id`
- `open`
- `high`
- `low`
- `close`
- `volume`

如果数据集中存在成交额、行业、板块等列，也允许一并带入。

### `FactorOutput.frame`

表示对整段研究区间计算后的因子结果。

推荐组织方式：

- index：`(trade_date, instrument_id)`
- columns：单个因子输出列，例如 `momentum_20`

也允许长表结构，但首版建议统一 MultiIndex + 单列输出，便于多个因子结果横向拼接。

## 9.3 因子行为约束

所有因子实现都必须满足：

1. `compute()` 不做 I/O
2. 不原地修改输入 DataFrame
3. 不读取系统当前时间
4. 同一输入得到同一输出
5. 输出结果不得包含未来数据

## 9.4 轻量因子管理

首版不做重型“因子管理模块”，只做一个轻量目录对象：

```python
class FactorCatalog(ABC):
    @abstractmethod
    def list_manifests(self) -> list[FactorManifest]: ...

    @abstractmethod
    def get(self, factor_id: str, version: str | None = None) -> Factor: ...
```

它负责：

- 列出当前可用因子
- 按 `factor_id` / `version` 获取因子实例

它不负责：

- 存数据库
- 做权限
- 管理生命周期审批

## 10. 标签模块设计

## 10.1 核心对象

```python
class LabelManifest(BaseModel):
    model_config = ConfigDict(extra="forbid")

    label_id: str
    label_name: str
    version: str
    description: str | None = None
    default_params: dict[str, Any]
    output_column: str


@dataclass(slots=True)
class LabelInput:
    dataset_spec: DatasetSpec
    frame: pd.DataFrame
    params: dict[str, Any]


@dataclass(slots=True)
class LabelOutput:
    label_id: str
    label_version: str
    frame: pd.DataFrame


class Label(ABC):
    @abstractmethod
    def manifest(self) -> LabelManifest: ...

    @abstractmethod
    def validate_params(self, params: dict[str, Any]) -> None: ...

    @abstractmethod
    def compute(self, input: LabelInput) -> LabelOutput: ...
```

## 10.2 首版标签范围

首版只建议支持最小标签集合，例如：

- 未来 `n` 日收益
- 未来 `n` 日超额收益
- 未来 `n` 日横截面收益排名

不建议首版直接做：

- 复杂分类标签体系
- 多阶段状态机标签
- 机器学习专用多目标标签

## 11. 因子评估模块设计

## 11.1 目标

评估模块的职责不是“替你决定一定能赚钱”，而是给出最小、可复验的因子有效性证据。

## 11.2 核心对象

```python
class FactorEvaluationRequest(BaseModel):
    model_config = ConfigDict(extra="forbid")

    factor_id: str
    factor_version: str
    label_id: str
    label_version: str
    group_count: int = 5


class FactorEvaluationSummary(BaseModel):
    model_config = ConfigDict(extra="forbid")

    coverage_rate: float
    ic_mean: float | None = None
    rank_ic_mean: float | None = None
    positive_ic_ratio: float | None = None
    long_short_return: float | None = None


@dataclass(slots=True)
class FactorEvaluationResult:
    request: FactorEvaluationRequest
    summary: FactorEvaluationSummary
    detail_frame: pd.DataFrame


class FactorEvaluator(ABC):
    @abstractmethod
    def evaluate(
        self,
        request: FactorEvaluationRequest,
        factor_output: FactorOutput,
        label_output: LabelOutput,
    ) -> FactorEvaluationResult: ...
```

## 11.3 首版评估口径

首版至少输出：

- 覆盖率 `coverage_rate`
- IC 均值 `ic_mean`
- RankIC 均值 `rank_ic_mean`
- IC 为正的比例 `positive_ic_ratio`
- 最高分组减最低分组的多空收益 `long_short_return`

更复杂的内容，例如：

- 行业中性 IC
- 月度 IC 分解
- 样本外稳定性分析
- 多标签交叉评估

统一延后。

## 12. 选股模块设计

## 12.1 核心对象

```python
class SelectorManifest(BaseModel):
    model_config = ConfigDict(extra="forbid")

    selector_id: str
    selector_name: str
    version: str
    description: str | None = None
    default_params: dict[str, Any]


@dataclass(slots=True)
class SelectionInput:
    dataset_spec: DatasetSpec
    factor_frame: pd.DataFrame
    params: dict[str, Any]


@dataclass(slots=True)
class SelectionRecord:
    trade_date: date
    instrument_id: str
    score: float
    rank: int
    selected: bool
    reason: str | None = None


@dataclass(slots=True)
class SelectionOutput:
    selector_id: str
    selector_version: str
    frame: pd.DataFrame


class Selector(ABC):
    @abstractmethod
    def manifest(self) -> SelectorManifest: ...

    @abstractmethod
    def validate_params(self, params: dict[str, Any]) -> None: ...

    @abstractmethod
    def select(self, input: SelectionInput) -> SelectionOutput: ...
```

## 12.2 选股输入输出语义

### `SelectionInput.factor_frame`

应当是一份对齐后的研究宽表：

- index：`(trade_date, instrument_id)`
- columns：一个或多个因子列

例如：

- `momentum_20`
- `volatility_20`
- `quality_score`

### `SelectionOutput.frame`

应包含：

- `trade_date`
- `instrument_id`
- `score`
- `rank`
- `selected`
- 可选 `reason`

## 12.3 首版支持的选股方式

首版只建议实现两类：

1. 单因子排序选股
2. 多因子线性加权打分选股

不建议首版直接做：

- 优化器求解型选股
- 行业中性约束选股
- 风险预算型组合构建

## 13. 与策略和回测的关系

这条链路在首版里应当明确为：

```text
ResearchFrame
-> Factor.compute()
-> Label.compute()
-> FactorEvaluator.evaluate()
-> Selector.select()
-> SelectionOutput
-> Strategy.generate_signals()
-> BacktestEngine.run()
```

这里最重要的边界是：

- `Selector` 产出的仍然是研究意义上的“入选结果”
- `Strategy` 负责把它包装成回测可消费的信号
- `BacktestEngine` 再把信号解释成 `top_n + 等权` 的持仓

也就是说：

- 因子不是策略
- 选股器也不是回测引擎
- 策略是研究结果进入回测运行时的适配层

## 14. 中间产物与导出物

首版不急着建正式表，建议先输出到本地产物目录：

```text
data/research/{run_id}/
  factor_values.parquet
  label_values.parquet
  factor_evaluation.json
  factor_evaluation_detail.csv
  selection_results.csv
```

说明：

- `factor_values.parquet`：因子结果
- `label_values.parquet`：标签结果
- `factor_evaluation.json`：评估摘要
- `factor_evaluation_detail.csv`：按日期或分组的详细评估结果
- `selection_results.csv`：每日选股结果

## 15. 与现有数据层的挂接方式

研究侧输入仍然来自当前已有的标准层：

1. `stock`
2. `trading_calendar`
3. `daily_quote`

引擎内部的数据准备逻辑需要把这些表组织成一份统一历史长表，然后再交给：

- `Factor`
- `Label`
- `Selector`

需要注意：

- 当前 `stock` 表还没有 `board`、`is_st` 等完整参考标签
- 如果后续要在研究侧按主板、创业板、科创板或 ST 做切片，必须先补参考数据

## 16. 建议的首版落地顺序

建议按以下顺序实现：

1. `factors/models.py` 与 `factors/base.py`
2. `labels/models.py` 与 `labels/base.py`
3. `evaluation/models.py` 与默认评估服务
4. `selection/models.py` 与 `selection/base.py`
5. `factors/catalog.py`
6. 再把 `SelectionOutput` 接到 `Strategy` 和 `BacktestEngine`

这个顺序的好处是：

- 先把研究对象边界钉死
- 再把因子到选股这条主链跑通
- 最后让策略和回测去消费已经稳定的研究结果

## 17. 首版测试清单

实现后至少要覆盖以下测试：

1. 给定统一历史 DataFrame，单因子能稳定输出因子结果
2. 因子输出不得包含未来日期数据
3. 标签结果与因子结果能按 `trade_date`、`instrument_id` 对齐
4. 评估服务能稳定产出 `coverage_rate`、`ic_mean`、`rank_ic_mean`
5. 单因子选股器能按分数稳定输出 `rank` 与 `selected`
6. 多因子线性加权选股器能按权重稳定输出综合分
7. 相同输入重复运行，因子结果、评估结果、选股结果一致
8. `SelectionOutput` 能被策略侧平滑转换为 `SignalRecord`

## 18. 当前明确延后的能力

这份设计明确延后：

- 因子管理后台
- 因子审批与发布流程
- 大规模因子挖掘平台
- 自动特征搜索
- 机器学习训练编排
- 分布式研究任务系统

## 19. 结论

当前更合理的主线不是直接把“策略”和“回测”做重，而是先把：

- 因子开发
- 标签定义
- 因子评估
- 基于因子的选股

这条研究链路做成稳定、轻量、可复验的运行时接口。

只要这条链路先跑通，后面的策略和回测就会自然收敛成更薄的一层，而不是反过来把研究逻辑塞进策略类里。
