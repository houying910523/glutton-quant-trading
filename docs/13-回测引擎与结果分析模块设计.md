# 回测引擎与结果分析模块设计

## 1. 目标

当前仓库已经有：

- `Context`
- `Factor`
- `Filter`
- `Selection`
- `FactorScoreStrategy`

`modules/backtest/` 也已经补出基础骨架。

本次设计目标不是一次性做完整回测，而是先把**统一策略接口、回测输入输出模型、调仓日调度、结果分析入口**固定下来，为后续最小可运行回测闭环提供稳定边界。

## 2. 当前收口原则

### 2.1 统一策略核心接口

当前统一采用：

```python
strategy.decide(context, portfolio_state) -> StrategyDecision
```

其中：

- `context`：当前时点可见市场数据
- `portfolio_state`：当前真实组合状态
- `StrategyDecision`：目标仓位建议

`BaseStrategy` 直接承接统一策略核心接口。

### 2.2 策略层与运行时分离

当前边界是：

- `BaseStrategy` 负责“决策”
- `BacktestEngine` / `BacktestRunner` 负责“推进状态与执行”

这使后续回测 / 模拟盘 / 实盘可以共享同一套策略核心。

## 3. 本次新增或收口的模块

### 3.1 `modules/strategies/models.py`

新增：

- `TargetPosition`
- `StrategyDecision`

用于表达低频组合类策略输出的“目标仓位建议”。

### 3.2 `modules/strategies/base.py`

`BaseStrategy` 已收口为统一决策式接口。

### 3.3 `modules/backtest/models.py`

本次定义最小回测模型：

- `BacktestConfig`
- `PortfolioPosition`
- `PortfolioState`
- `OrderIntent`
- `FillRecord`
- `TradeRecord`
- `EquityPoint`
- `PositionSnapshot`
- `BacktestSummary`
- `PeriodReturn`
- `BacktestResult`
- `BacktestAnalyzeResult`

### 3.4 `modules/backtest/scheduler.py`

新增 `RebalanceScheduler`，先支持：

- `daily`
- `weekly`
- `monthly`

负责把交易日列表收敛成调仓日列表。

### 3.5 `modules/backtest/engine.py`

当前已经实现最小回测执行流与公共辅助能力：

- 校验 `BacktestConfig`
- 读取开市日列表
- 生成调仓日列表
- 创建初始 `PortfolioState`
- 构造 `Context`
- 调用 `strategy.decide(context, portfolio_state)`
- 将 `StrategyDecision` 解释成调仓订单
- 在下一个交易日按 `next_open` 执行成交
- 推进组合状态
- 按收盘价生成净值曲线与持仓快照
- 输出订单与成交记录
- 已加入 A 股基础执行约束：`T+1`、整手买入、一字涨跌停的保守拦截

### 3.6 `modules/backtest/analyzer.py`

先实现一个可独立工作的分析器：

- 从 `equity_curve` 推导收益率、年化、波动率、夏普、最大回撤
- 生成月度 / 年度收益摘要
- 生成最大回撤区间

### 3.7 `modules/backtest/runner.py`

定义统一入口：

```python
BacktestRunner.run(strategy, config)
```

职责是组织：

- `engine.run()`
- `analyzer.analyze()`

而不是在 runner 里直接写撮合和净值推进逻辑。

## 4. 当前明确不做的部分

本次代码骨架**仍不**包含：

- 更完整的停牌处理与涨跌停细化规则
- 闭合交易生成逻辑
- 回测结果持久化

## 5. 下一步实现顺序

建议按下面顺序继续补：

1. `BaseStrategy.decide()` 输出到更完整订单意图的转换
2. 停牌处理、涨跌停细化和更多市场规则
3. `TradeRecord` 闭合逻辑
4. 更多组合与风控约束
5. 回测结果持久化与报告层

## 6. 当前结论

当前 `modules/backtest/` 已形成：

- 统一策略核心接口
- 回测输入输出模型
- 调仓日调度器
- 最小回测执行流（固定调仓、`next_open` 成交、收盘估值、净值曲线、持仓快照、订单/成交记录）
- A 股基础执行约束（`T+1`、整手买入、一字涨跌停保守拦截）
- 分析模块
- runner 入口

但要注意：

> 当前已经有可运行的 MVP 回测闭环，并已加入 A 股基础执行约束；但停牌处理、闭合交易和更复杂的组合控制还需要后续继续实现。
